# Claude Code News Digest — 2026-07-18

## Overview
The week of July 13–17 (Week 29, v2.1.207–v2.1.212) brought two headline features to Claude Code: published Artifacts can now call live MCP connectors so dashboards show real-time data, and a new screen reader mode makes the CLI fully accessible via VoiceOver and NVDA. These land on top of the previous week's equally substantial additions — a built-in browser on Desktop and a diagnostic `/doctor` command — marking a notably productive fortnight for the platform.

---

## New Features & Releases

- **Artifacts Call Live MCP Connectors (Week 29 · v2.1.207–v2.1.212)**: Published artifact pages can now pull live data and trigger actions through the *viewer's own* MCP connectors on every page load, turning static output snapshots into fully interactive, real-time dashboards. This week also adds public sharing links, editor roles for collaborative editing on Team and Enterprise plans, and the ability to create artifacts from Claude Tag sessions. Source: https://code.claude.com/docs/en/whats-new/2026-w29

- **Screen Reader Mode (Week 29 · v2.1.207–v2.1.212)**: Claude Code now has a first-class accessibility mode (`--ax-screen-reader` flag, `CLAUDE_AX_SCREEN_READER` env var, or `axScreenReader` setting) that replaces boxes, spinners, and in-place terminal redraws with plain sequential labeled lines, enabling full use with VoiceOver, NVDA, and other screen readers. Source: https://code.claude.com/docs/en/whats-new/2026-w29

- **In-App Browser on Desktop (Week 28 · v2.1.202–v2.1.206)**: Claude Code Desktop gained a sandboxed built-in browser this week, allowing Claude to browse external docs, designs, or any site and interact with pages — click-through, read, and navigate — just as it already does with local dev server previews. Safety classifiers review actions on external sites, and session persistence is user-configurable. Source: https://code.claude.com/docs/en/whats-new/2026-w28

- **`/doctor` Full Setup Checkup (Week 28 · v2.1.205)**: The `/doctor` command (aliased as `/checkup`) evolved from a read-only report into a full diagnostic-and-repair tool. It checks installation health, finds unused skills/MCP servers/plugins relative to their context cost, deduplicates local `CLAUDE.md` against checked-in versions, proposes trimming derivable content, and flags slow hooks — reporting findings first and asking for confirmation before making any changes. Source: https://code.claude.com/docs/en/whats-new/2026-w28

## Integrations & Extensions

- **Auto Mode GA on Third-Party Cloud Providers (Week 29)**: Auto mode no longer requires the `CLAUDE_CODE_ENABLE_AUTO_MODE` opt-in environment variable on Amazon Bedrock, Google Cloud's Agent Platform, or Microsoft Foundry. Administrators can disable it with the `disableAutoMode` setting. Amazon Bedrock, Google Cloud Agent Platform, and Claude Platform on AWS also now default to Claude Opus 4.8. Source: https://code.claude.com/docs/en/whats-new/2026-w29

- **Enterprise-Managed MCP Connector Access**: Anthropic launched centralized enterprise MCP connector provisioning, starting with Okta. Admins provision connectors once and users get zero-touch access on first login across Claude chat, Claude Code, and Cowork. Asana, Atlassian, Canva, Figma, Granola, Linear, and Supabase support enterprise-managed auth at launch; Slack support is coming soon. Source: https://code.claude.com/docs/en/whats-new

- **Claude AI Boost in VS Code 1.128 (July 8)**: VS Code version 1.128 shipped additional Claude AI enhancements to the Claude Code extension, continuing the integration improvements that make Claude Code's native graphical diff view, permission gates, and @-mention context richer within the IDE. The JetBrains plugin also received corresponding reliability updates. Source: https://visualstudiomagazine.com/articles/2026/07/08/claude-ai-gets-yet-another-boost-in-vs-code-1-128.aspx

- **Corporate Launcher Support (Week 29)**: A new `CLAUDE_CODE_PROCESS_WRAPPER` env var (or `processWrapper` setting) routes all processes Claude Code spawns — background service, agent view sessions — through a required corporate wrapper executable, addressing enterprise deployment requirements. Source: https://code.claude.com/docs/en/whats-new/2026-w29

## Bug Fixes & Performance

- **MCP Long-Running Tool Auto-Backgrounding (Week 29)**: MCP tool calls that run longer than 2 minutes now automatically move to the background, keeping the session responsive. The threshold is configurable via `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`. Source: https://code.claude.com/docs/en/whats-new/2026-w29

- **Session-Wide Runaway-Loop Caps (Week 29)**: New per-session caps prevent runaway delegation and search loops: WebSearch calls default to 200 (`CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`) and subagent spawns default to 200 (`CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`), both tunable. Source: https://code.claude.com/docs/en/whats-new/2026-w29

- **Auto-Update Memory Reduction (Week 28)**: Binary auto-update downloads now stream to disk instead of buffering entirely in memory, cutting peak updater memory usage by approximately 400 MB. Source: https://code.claude.com/docs/en/whats-new/2026-w28

- **Background Agents Upgrade Immediately (Week 28)**: Background agents now upgrade to the latest Claude Code version immediately after an update, rather than incurring the slow stale-session upgrade cost when you first attach. Source: https://code.claude.com/docs/en/whats-new/2026-w28

- **Fabricated In-Transcript Approval Prevention (Week 28)**: Background task notifications now explicitly assert that no human input has occurred since the last genuine user message, closing a potential attack surface where injected transcript content could impersonate user approval. Source: https://code.claude.com/docs/en/whats-new/2026-w28

- **Persistent "Always Allow" Rules Across Worktrees (Week 29)**: Permission rules saved as "always allow" now save at the repository root rather than the session's working directory, so approvals granted in any git worktree persist across sessions and worktrees. Source: https://code.claude.com/docs/en/whats-new/2026-w29

## Community & Ecosystem

- **Anthropic Blog: Large-Scale Code Migrations with Claude Code (July 16)**: Anthropic published a practical walkthrough of how they run large-scale internal code migrations using Claude Code, providing a blueprint for engineering teams wanting to adopt agentic workflows for codebase-wide changes. Source: https://www.anthropic.com/news

- **Agent SDK Billing Decoupled from Plan Limits**: As of June 15, 2026, Claude Agent SDK usage (Python v0.2.120+, TypeScript) no longer counts against Claude plan usage limits — plan limits are now reserved for interactive Claude Code, Claude Cowork, and Claude.ai sessions. This makes the SDK more attractive for automated pipelines and CI use cases. Source: https://code.claude.com/docs/en/agent-sdk/overview

- **`/fork` and `/subtask` Workflow Split (Week 29)**: `/fork` now copies the current conversation into a new independent background session visible in `claude agents`, freeing the main session to continue. The old in-session forked subagent behavior has been promoted to its own command, `/subtask`, giving teams two distinct delegation patterns. Source: https://code.claude.com/docs/en/whats-new/2026-w29

## Key Takeaway
The most significant development this week is **Artifacts with live MCP connector data**: published Claude Code artifact pages can now serve as real-time, action-capable dashboards that pull from each viewer's own connected services (GitHub, Jira, Slack, Supabase, and others), fundamentally expanding what "sharing a Claude Code result" means — from a static snapshot to a live, collaborative tool.
