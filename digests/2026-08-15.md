# Claude Code News Digest — 2026-08-15

## Overview
The biggest Claude Code story today is the rollout of auto mode as the default permission setting for Pro, Max, and Team plan sessions, which went live on August 14. Alongside this, releases v2.1.231–v2.1.233 (August 12–14) delivered expanded GitLab support, cross-session `@` mention messaging, default subagent forking, and a string of security and reliability fixes — including a patched NTLM credential-leak vector on Windows.

## New Features & Releases

- **Auto mode now default for Pro, Max & Team (v2.1.232)**: Starting August 14, auto mode is the default permission mode for new Claude Code sessions on Pro, Max, and Team plans. In auto mode Claude proceeds autonomously unless an action is judged irreversible or destructive. The previous opt-in variable is no longer required. Source: https://code.claude.com/docs/en/whats-new

- **Subagent forking enabled by default (v2.1.232)**: `subagent_type: "fork"` now inherits the full conversation and prompt cache without any configuration change. Non-teammate agent spawns in interactive sessions also run in the background by default. Source: https://code.claude.com/docs/en/changelog

- **Cross-session `@` mention messaging (v2.1.232)**: Type `@session-name` in any prompt to address a running Claude session directly, letting Claude hand off findings or decisions between sessions without user re-explanation. Interactive sessions now keep unique names (duplicates get a `name-word-word` variant). Source: https://code.claude.com/docs/en/changelog

- **GitLab MR support in `--worktree` and agents view (v2.1.233)**: Merge request URLs are now supported in the `--worktree` flag and the `claude agents` panel, displayed as `!N` alongside GitHub PRs. GitLab token families (`glrt-`, `gloas-`, `glptt-`, `glagent-`) are also now redacted from logs. Source: https://code.claude.com/docs/en/changelog

- **Remote Control `--continue` flag (v2.1.229)**: `claude remote-control --continue` resumes the most recent Remote Control session, removing the need to copy session identifiers manually. Source: https://code.claude.com/docs/en/changelog

- **WebFetch cache TTL now configurable (v2.1.233)**: The new `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` environment variable overrides the default 15-minute session URL cache, giving teams control over how aggressively fetched pages are reused. Source: https://code.claude.com/docs/en/changelog

## Integrations & Extensions

- **Self-hosted environments in public beta**: Team and Enterprise plans can now run Claude Code cloud sessions on their own machines or containers via `claude self-hosted-runner`. Server-supplied Claude Code hooks are also now supported in self-hosted runner sessions (v2.1.229). Source: https://code.claude.com/docs/en/whats-new

- **VS Code Focus view & IDE reliability fixes (v2.1.229)**: The VS Code extension gained a Focus view in the Week 32 update. The same release fixed multi-second UI stalls when editing files with thousands of IDE diagnostics and resolved file-watcher handle leaks after atomic file replacements. Source: https://code.claude.com/docs/en/whats-new

- **GitLab support in plugin marketplaces (v2.1.232)**: Plugin marketplace discovery now works with GitLab-hosted plugin sources, extending the ecosystem beyond GitHub-only repositories. Enterprise policy adds `blockedMarketplaces` URL entries for git clone URLs. Source: https://code.claude.com/docs/en/changelog

- **SSE keepalive pings for gateway streaming (v2.1.229)**: Long thinking pauses no longer trigger idle-timeout disconnects from gateway streaming responses, improving stability for Vertex, Foundry, and Claude Platform on AWS. Source: https://code.claude.com/docs/en/changelog

- **Compliance API beta for Claude Code**: Anthropic expanded its Compliance API to cover Claude Code across desktop, web, mobile, and CLI surfaces. Claude Enterprise customers in beta can pull unified session content and metadata for audits and eDiscovery. Source: https://releasebot.io/updates/anthropic/claude-code

## Bug Fixes & Performance

- **Windows NTLM credential-leak vector patched (v2.1.233)**: The Windows NT `\??\` device prefix that allowed UNC path validation bypass — a potential NTLM credential-leak vector — has been fixed. Source: https://code.claude.com/docs/en/changelog

- **MCP OAuth redirect URI mismatch fixed (v2.1.231)**: MCP OAuth sign-in was failing with a redirect URI mismatch for servers using pre-registered OAuth clients such as Slack. Now resolved. Source: https://code.claude.com/docs/en/changelog

- **MCP v2 subscription loop fixed (v2.1.233)**: MCP v2 connections that endlessly reopened subscriptions/listen streams have been corrected. A separate fix resolved MCP connections hanging on malformed protocol-version responses (v2.1.232). Source: https://code.claude.com/docs/en/changelog

- **Linux sandbox CPU spin fixed (v2.1.233)**: Idle sessions on Linux were keeping one CPU core at 100% when sandboxing was enabled. This regression is now patched. Source: https://code.claude.com/docs/en/changelog

- **Auto mode Bash regression fixed (v2.1.233)**: A regression introduced in v2.1.232 caused auto mode to repeatedly stop on ordinary `cd <dir> && <command> > file` Bash commands. Resolved the same day in v2.1.233. Source: https://code.claude.com/docs/en/changelog

- **Remote Control stability improvements (v2.1.232)**: Multiple Remote Control fixes landed: sessions no longer inherit cloud session transcripts/credentials, no longer appear unreachable while idle, and Remote Control keeps reconnecting ~30 minutes after network blips. Source: https://code.claude.com/docs/en/changelog

- **Notification hooks now fire in Desktop and VS Code (v2.1.233)**: Notification hooks were silently not firing for permission prompts inside Claude Desktop and VS Code. Fixed. Source: https://code.claude.com/docs/en/changelog

## Roadmap & Announcements

- **Auto mode default rollout complete**: The August 14 auto mode default went live on schedule for Pro, Max, and Team plans. Anthropic's direction is clear: reduce friction for autonomous coding work while using a background classifier to block genuinely risky actions. Source: https://code.claude.com/docs/en/whats-new

- **Self-hosted environments expanding**: Self-hosted runner environments are in public beta on Team and Enterprise plans, signalling Anthropic's push into enterprise infrastructure and security-sensitive deployment scenarios. Source: https://code.claude.com/docs/en/whats-new

- **Todo/task tools disabled on newer models**: As of v2.1.233, the built-in todo/task-tracking tools are disabled by default on Opus 4.8, Sonnet 5, Fable 5, and Mythos 5+. Users who rely on them must set `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`. This appears to be a step toward skills/plugins replacing built-in tools. Source: https://code.claude.com/docs/en/changelog

## Key Takeaway
The landmark development of the week is **auto mode becoming the default** for Pro, Max, and Team plans starting August 14 — a fundamental shift from Claude Code as an interactive assistant to an autonomous coding agent that self-governs routine actions and only surfaces truly risky decisions. This, combined with default subagent forking and cross-session `@` messaging, positions Claude Code as a serious multi-agent orchestration platform for everyday development.
