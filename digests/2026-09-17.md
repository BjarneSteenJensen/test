# Claude Code News Digest — 2026-09-17

## Overview
Today marks the release of Claude Code v2.1.274, the latest in a rapid cadence of September updates that have focused heavily on MCP reliability, LLM gateway observability, and self-healing session stability. The week's biggest theme is production-hardening: corrupted transcripts now self-heal, MCP HTTP connections are significantly more robust, and enterprise gateway operators gain a rich new set of OpenTelemetry instrumentation hooks.

## New Features & Releases

- **v2.1.274 Released Today (September 17)**: Adds a visible warning for critical memory usage with guided recovery steps, a new `CLAUDE_CODE_MCP_STARTUP_WAIT_MS` environment variable to control MCP server connection wait time, an `effort` attribute on OpenTelemetry trace spans, a `claude_code.managed_settings_resolved` OTel event, and click-to-expand for collapsed teammate/agent messages in fullscreen mode. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **v2.1.271 — Fast Mode in Remote Sessions (September 14)**: Fast mode support arrives in Claude Code Remote sessions (cloud and self-hosted runners), so teams that have fast mode enabled at the org level can now use it in remote contexts. Also adds mouse support to the `/config` panel in fullscreen mode, `--accept-command <sha256>` for verified plugin installs, and per-command `allowed_domains` in auto mode. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **v2.1.269 — `claude plugin eval` (September 11)**: The new `claude plugin eval` command lets developers run their plugin against a test suite, score results, and compare against a no-plugin baseline. `claude plugin eval init` drafts the test cases and graders automatically. Also adds `/output-style [name]`, diffs of files changed by Bash commands, and a `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` cap (1–256). Source: [What's New — Week 37](https://code.claude.com/docs/en/whats-new)

- **v2.1.267 — `maxEffortLevel` Setting (September 9)**: A new `maxEffortLevel` setting lets admins and users cap the effort level applied across all providers, preventing runaway context spend on routine tasks. Also adds `--system-prompt-snapshot off` for evaluation harnesses. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

## Integrations & Extensions

- **Xcode 26.3 + Claude Agent SDK Native Integration**: Xcode 26.3 introduces a native integration with the Claude Agent SDK — the same underlying harness that powers Claude Code — giving Apple platform developers the full Claude Code experience (subagents, background tasks, plugins) directly inside Xcode without leaving the IDE. Source: [Anthropic News — Apple Xcode Claude Agent SDK](https://anthropic.com/news/apple-xcode-claude-agent-sdk)

- **New LLM Gateway Request Headers (v2.1.273, September 15)**: Enterprise LLM gateways now receive five new hint headers on every Claude Code request: `x-claude-code-request-class`, `x-claude-code-agent-type`, `x-claude-code-prev-tool-durations`, `x-claude-code-compaction`, and `x-claude-code-context-compacted`. These enable downstream routing, cost attribution, and observability without parsing payloads. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **Remote Control Session Forking (v2.1.273)**: Sessions started with `claude --remote-control` can now be forked from the Claude app; the fork runs as a background session on the user's local machine, enabling seamless handoff from mobile to desktop workflows. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **MCP Server HTTP Transport Fixes (v2.1.265, September 8)**: HTTP-configured MCP servers that only speak the legacy HTTP+SSE transport were silently failing to connect; this is now fixed with proper fallback. The `--plugin-dir` flag also now accepts a folder containing multiple plugins for batch discovery. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

## Bug Fixes & Performance

- **Self-Healing Corrupted Transcripts (v2.1.274)**: Sessions that encountered `unexpected tool_use_id` 400 errors were previously stuck in a retry loop indefinitely. Corrupted transcripts now auto-repair, and the error is surfaced cleanly rather than silently looping. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **Streamable HTTP MCP Timeout Fixed (v2.1.274)**: Streamable HTTP MCP tool calls were timing out after exactly 5 minutes regardless of workload. This ceiling has been removed and replaced with properly bounded timeout handling. MCP prompts and resources also now refresh correctly on `list-changed` notifications. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **Git Permission Regression Fixed (v2.1.270, September 12)**: A regression introduced in v2.1.269 caused read-only git commands (e.g., `git log`, `git status`) to unexpectedly trigger permission prompts during long sessions. Patched in the same release cycle. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **WebFetch Hang Fixed (v2.1.268, September 10)**: Pages that were slow to download could cause `WebFetch` to hang indefinitely. The tool now enforces a 300-second (5-minute) hard timeout and fails with a clear error rather than blocking the session. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **Gateway Auth Regression Fixed (v2.1.266, September 8)**: v2.1.265 accidentally forced Cloud-gateway sign-in via `CLAUDE_CODE_USE_GATEWAY`, breaking API key and third-party gateway configurations. Patched within the same day. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

## Key Takeaway
The release of v2.1.274 on September 17 completes a week of intensive reliability and observability work: corrupted transcripts now self-heal, MCP HTTP connections are substantially more robust, and gateway operators gain a rich new OpenTelemetry surface — making this one of the most enterprise-hardening weeks in Claude Code's recent history.
