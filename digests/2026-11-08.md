# Claude Code News Digest — 2026-11-08

## Overview
The week of November 8, 2026 brought three Claude Code point releases (v2.1.317–2.1.319), culminating in background MCP task execution and tighter auto-mode permission controls. The biggest off-release story is a credential-exposure vulnerability in the "Don't Ask Again" approval feature, with researchers finding 2,539 leaked secrets across nearly 2,000 public GitHub repositories.

---

## New Features & Releases

- **v2.1.319 (Nov 6): Background MCP tasks & permission hardening**: Claude Code now moves MCP server task tool calls to the background immediately, reporting results to Claude when they finish. The same release adds `permissions.denyInsteadOfPrompting`, which denies any tool call that would wait on a permission prompt so the turn continues unattended. Auto mode no longer falls back to the built-in classifier behind LLM gateways — calls the server cannot check are asked about or denied; set `CLAUDE_CODE_AUTO_MODE_SERVER=0` to restore the old behaviour. Source: https://code.claude.com/docs/en/changelog

- **v2.1.318 (Nov 4): Auth expiry visibility & subagent reliability**: `claude auth status` now reports when a stored claude.ai sign-in expires (`loginExpiresAt`), and `claude -p` JSON output includes `credential_expires_at`, with a 10-day warning in text mode. Background subagents automatically move long-running shell commands to the background after 3 minutes to prevent prompt-cache expiry. The IDE extension is no longer auto-installed when Claude Code starts inside an IDE terminal — use `/ide` from an outside terminal instead. Source: https://code.claude.com/docs/en/changelog

- **v2.1.317 (Nov 3): SDK hooks, OpenTelemetry & gateway cost API**: Agent SDK hook callbacks now accept `onFailure: "block"`, causing a failing callback to block the action rather than letting it proceed. New OpenTelemetry attributes (`anthropic.plan`, `anthropic.seat_type`, `anthropic.provider`, `anthropic.custom_base_url`) appear on metrics, events, and spans. A new cost report endpoint (`GET /v1/organizations/analytics/cost`) lets Claude Apps gateway users query past spend by total, developer, day, or IdP group. Source: https://code.claude.com/docs/en/changelog

## Integrations & Extensions

- **MCP protocol v2026-07-28 now default**: Cloud session and Remote Control MCP connectors negotiate MCP protocol revision 2026-07-28 by default (since v2.1.299), reflecting the most substantial spec revision since authorization was added in July 2026. The new `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` env var gives teams running synchronous tool servers an escape hatch. Source: https://code.claude.com/docs/en/mcp

- **VS Code extension no longer auto-installed**: Starting with v2.1.318, Claude Code stops silently installing or updating the VS Code/Cursor/JetBrains extension when launched inside an IDE terminal. Users must run `/ide` from an external terminal, giving more control over extension versions. Official VS Code guide: https://code.claude.com/docs/en/vs-code

## Bug Fixes & Performance

- **`claude -p` exit code fixed**: Prior to v2.1.317, `claude -p` exited with code 0 even when a full disk caused transcript writes to fail. It now exits 1 in both text and JSON modes. Source: https://code.claude.com/docs/en/changelog

- **Bash permission bypass patched (v2.1.318)**: A bug that allowed a crafted environment variable prefix to bypass Bash tool permission checks was fixed in this release. Source: https://code.claude.com/docs/en/changelog

- **`--continue` conversation loss fixed**: The v2.1.318 release fixed `--continue` dropping earlier conversation context after a malformed tool call retry. Source: https://code.claude.com/docs/en/changelog

## Community & Ecosystem

- **Credential exposure via `.claude/settings.local.json`**: Security researchers at Apiiro disclosed that Claude Code's "Don't Ask Again" approval flow saves the full approved shell command — including any embedded secrets — to `.claude/settings.local.json`. They found 2,539 credentials (API keys, tokens, passwords) across 1,994 public GitHub repositories. Developers are advised to rotate any exposed credentials and add `.claude/settings.local.json` to `.gitignore`. Sources: https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html · https://gbhackers.com/claude-codes-dont-ask-again-feature-exposed/

- **Game-cloning policy triggers backlash, then partial rollback**: Anthropic added two sentences to Claude Code's system prompt for Opus 5.5 to prevent recreating existing video games, citing IP policy. Developers immediately reported overblocking — refusals on crash-dump analysis, anti-cheat tooling, and their own original projects. Anthropic reportedly relaxed the restrictions in v2.1.317, though only one source confirmed this at time of writing. Sources: https://80.lv/articles/claude-code-blocks-video-game-cloning-some-reverse-engineering-tasks · https://www.heise.de/en/news/Claude-Code-Anthropic-tightens-rules-on-game-clones-11508408.html · https://beincrypto.com/anthropic-claude-blocks-video-game-cloning/

## Roadmap & Announcements

- **Opus 4.8 fast mode deprecated — removal November 30, 2026**: As of v2.1.316 (Oct 31), fast mode for `claude-opus-4-8` is deprecated. Requests will return an error after November 30, 2026. Anthropic recommends migrating to Opus 5.5, which provides the same speed benefit. Source: https://code.claude.com/docs/en/changelog

- **New Usage Policy takes effect November 12, 2026**: Anthropic published a 2026 Usage Policy update on October 8, 2026, effective November 12 — particularly relevant for teams running unattended agents and automated workflows with Claude Code. Source: https://releasebot.io/updates/anthropic

---

## Key Takeaway
The credential-exposure bug in `.claude/settings.local.json` is the most urgent item for Claude Code users today: check your public repositories for exposed secrets and add that file to your `.gitignore` immediately. On the product side, background MCP tasks (v2.1.319) and the new `permissions.denyInsteadOfPrompting` flag represent meaningful steps toward safer, fully unattended agentic workflows.
