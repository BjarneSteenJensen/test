# Claude Code News Digest — 2026-09-12

## Overview
September 12, 2026 marks a period of intense release activity for Claude Code, with 13 versions shipped since September 1. The headline changes are: Claude Fable 5.1 becomes the new default model with 1 million token context, organizations gain centrally managed MCP server deployments, and a new plugin evaluation framework (`claude plugin eval`) lands alongside output-style switching. Dozens of prompt-cache, terminal, and session-reliability fixes round out a busy fortnight.

---

## New Features & Releases

- **Claude Fable 5.1 as default model (v2.1.257, Sep 1)**: `claude-fable-5-1` replaces the previous default Fable model, adding 1M token context window and revised pricing at $10/$50 per Mtok with $0.25/Mtok cache reads. A `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` env var allows pinning subagents to a specific model, and the `[1m]` suffix is now properly honored throughout. Source: https://code.claude.com/docs/en/changelog

- **Plugin Evaluation suite (`claude plugin eval`) (v2.1.269, Sep 11)**: Developers can now run a plugin's eval suite against Claude Code and receive scored, reproducible results as both a JSON and an HTML report, enabling CI-friendly plugin quality gates. Source: https://code.claude.com/docs/en/changelog

- **Output Style switching (`/output-style`) (v2.1.269, Sep 11)**: A new `/output-style [name]` command lets users list and switch output styles across Remote Control, cloud, and headless sessions from within a conversation. Source: https://code.claude.com/docs/en/changelog

- **Diff panel for uncommitted changes (`/diff`) (v2.1.260, Sep 3)**: `/diff` opens an inline panel showing uncommitted changes beside the active conversation in fullscreen mode, complemented by likely cache-miss causes added to `/cost`. Source: https://code.claude.com/docs/en/changelog

- **Time format & timezone settings (v2.1.257, Sep 1)**: New `timeFormat` (12h, 24h, 24h UTC, or strftime pattern) and `timeZone` settings control the turn-end clock and all transcript timestamps. Source: https://code.claude.com/docs/en/changelog

- **Containment Escape rule in auto mode (v2.1.257, Sep 1)**: Cloud metadata-credential fetches, egress evasion, and cross-tenant reach are no longer auto-approved unless the environment marks them expected — a meaningful security tightening for unattended/CI usage. Source: https://code.claude.com/docs/en/changelog

- **`maxEffortLevel` per-model cap (v2.1.267, Sep 9)**: A new `maxEffortLevel` setting (top-level or per-model) lets admins and users cap effort across all providers, preventing runaway token spend on costly reasoning modes. Source: https://code.claude.com/docs/en/changelog

- **Workflow concurrency control (v2.1.269, Sep 11)**: `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` (1–256) lets operators raise the concurrent agent ceiling for inference-bound fan-outs. Source: https://code.claude.com/docs/en/changelog

- **Claude Code usage limits permanent increase (Sep 14, upcoming)**: Anthropic will replace its temporary 50% weekly boost with a permanent 25% increase to Claude Code usage limits starting September 14. Source: https://www.explainx.ai/blog/anthropic-claude-code-limits-17-percent-cut-september-2026-august-2026

## Integrations & Extensions

- **Managed MCP servers for organizations (v2.1.259/2.1.265, Sep 2–8)**: A new `managedMcpServers` setting lets organizations push HTTP and SSE MCP servers to every user via a platform file (`/etc/claude-code/managed-mcp.json` on Linux, `/Library/Application Support/ClaudeCode/managed-mcp.json` on macOS). When deployed, users receive only those servers plus in-process servers — they cannot add or modify others. Source: https://code.claude.com/docs/en/changelog

- **GitLab MR recognition (v2.1.259, Sep 2)**: `glab mr` commands are now recognized alongside `gh pr`, enabling `/code-review --comment` and MR tracking workflows on GitLab repositories. Source: https://code.claude.com/docs/en/changelog

- **VS Code: Agent map, Hooks dialog, Permission rules dialog (v2.1.260/2.1.269, Sep 3–11)**: The VS Code extension gained an agent map footer pill showing active sub-agents with Stop buttons and read-only transcripts, plus new dialogs for browsing and managing hooks and permission rules. Source: https://code.claude.com/docs/en/changelog

- **VS Code: Automatic session archiving (v2.1.261/2.1.265, Sep 4–8)**: Inactive sessions are now automatically archived after a configurable period (default 14 days), keeping the session list tidy without losing history. Source: https://code.claude.com/docs/en/changelog

- **Plugin directory support (`--plugin-dir`) (v2.1.265, Sep 8)**: `--plugin-dir` can now point to a folder of plugins with dynamic loading, making it easier to bundle and distribute collections of tools. Source: https://code.claude.com/docs/en/changelog

- **Gateway pricing in managed settings (v2.1.268, Sep 10)**: `pricing:` support in `gateway.yaml` allows signed-in Claude Code clients to receive configured rates through managed settings, so `/cost` and telemetry align with the spend meter. Source: https://code.claude.com/docs/en/changelog

- **OpenTelemetry repository tagging (v2.1.269, Sep 11)**: `OTEL_METRICS_INCLUDE_REPOSITORY` tags metrics with `vcs.*` repository attributes; commit events now get `vcs.ref.head.*` when `OTEL_LOG_TOOL_DETAILS` is set, enabling richer observability dashboards. Source: https://code.claude.com/docs/en/changelog

- **Claude Agent SDK: Compliance API out of beta**: The Claude Developer Platform released Compliance API session endpoints out of beta for Cowork and Claude Code sessions, alongside Admin API support in the `ant` CLI and multiple SDKs. Source: https://releasebot.io/updates/anthropic/claude-developer-platform

## Bug Fixes & Performance

- **Prompt cache stability (multiple versions)**: September's most-fixed area was prompt caching. Fixes included partial cache invalidation on token-limit resume (v2.1.269), OAuth token refresh cache breaks (v2.1.259), Fable 5.1 caching only covering the first part (v2.1.260), and prompt-cache misses in cloud sessions (v2.1.269). Source: https://code.claude.com/docs/en/changelog

- **macOS Monterey launch regression fixed (v2.1.258, Sep 1)**: A critical regression introduced in v2.1.255 prevented Claude Code from launching on macOS 12 (Monterey); fixed same day alongside a fix for remote/scheduled session failures after permission re-send. Source: https://code.claude.com/docs/en/changelog

- **WebFetch timeout fix (v2.1.268, Sep 10)**: WebFetch was hanging indefinitely; it now fails after 300 seconds (configurable via `CLAUDE_CODE_WEBFETCH_DEADLINE_MS`). Source: https://code.claude.com/docs/en/changelog

- **`CLAUDE_CODE_USE_GATEWAY` regression fixed (v2.1.266, Sep 8)**: A v2.1.265 regression incorrectly forced Cloud-gateway sign-in when `CLAUDE_CODE_USE_GATEWAY` was set; the variable is now ignored unless both `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` are present. Source: https://code.claude.com/docs/en/changelog

- **Terminal rendering fixes (v2.1.269, Sep 11)**: Escape codes and UI glitches corrected for kitty, st, rxvt-unicode, and WezTerm; emoji/flag splitting across wrapped lines fixed in v2.1.260; synchronized output fixes for GNOME Terminal and Konsole. Source: https://code.claude.com/docs/en/changelog

- **Startup performance improvements**: v2.1.251 delivered 50ms faster subagent turns; v2.1.265 improved `--worktree` startup parallelization; v2.1.260 improved `--resume` first-render time and session responsiveness for long sessions. Source: https://code.claude.com/docs/en/changelog

## Key Takeaway

The single biggest Claude Code development this week is the combination of **Claude Fable 5.1 becoming the default model with 1M token context** and **managed MCP server deployment for organizations** — together these dramatically expand what teams can do with Claude Code at enterprise scale, handling larger codebases in a single context window while administrators lock down and provision exactly the tool integrations each user needs.
