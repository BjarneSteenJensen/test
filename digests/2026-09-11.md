# Claude Code News Digest — 2026-09-11

## Overview
September 11, 2026 sees Claude Code at version 2.1.268, released the previous day, with a strong focus on gateway pricing support, a new fullscreen diff panel, and WebFetch reliability improvements. The broader September release cadence has been intense — nine versions in eleven days — reflecting rapid iteration on stability, VS Code integration, managed MCP servers, and the newly default Claude Fable 5.1 model.

## New Features & Releases

- **v2.1.268 (Sep 10): Diff panel, gateway pricing, and WebFetch deadline**: The latest release adds a `/diff` panel for viewing uncommitted changes directly in fullscreen mode and introduces pricing support to the Claude apps gateway. A major reliability fix prevents WebFetch from hanging indefinitely — it now times out after 300 seconds (configurable via `CLAUDE_CODE_WEBFETCH_DEADLINE_MS`). Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **v2.1.267 (Sep 9): `maxEffortLevel` setting and fresh system prompts**: Users and organizations can now cap the effort level on every provider (Bedrock, Vertex, Foundry) using the new `maxEffortLevel` managed setting. A new `--system-prompt-snapshot off` flag forces the system prompt to be rendered fresh on every request instead of reusing the cached conversation prompt — useful when iterating on prompt text. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **v2.1.261 (Sep 4): Output limits, `/skill-doctor`, and org policy diagnostics**: `bashOutputMaxChars` and `taskOutputMaxChars` settings allow raising inline command/task output up to 128K characters before it is saved to a file. The new `/skill-doctor` command identifies skills that are loaded but unused. An organization policy line was added to `/status` and `claude doctor` explaining why an org policy could not be loaded. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **v2.1.257 (Sep 1): Claude Fable 5.1 becomes default model**: Claude Fable 5.1 with 1M context is now the default Fable model in Claude Code, accompanied by new time format and timezone settings and significant VS Code and cloud session improvements. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

## Integrations & Extensions

- **Managed MCP servers for organizations (v2.1.259, Sep 2)**: A new `managedMcpServers` managed setting allows organizations to push HTTP/SSE MCP servers to all users automatically. A concurrent-sessions bug that caused sessions to silently overwrite each other's `~/.claude.json` — losing MCP state and workspace trust — has also been fixed. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **VS Code integration improvements across multiple versions**: The September release wave added automatic archiving of inactive VS Code sessions (default 14 days), a fold button on permission/question prompts, an "Archive session" right-click menu entry, a single flat-list model picker, and fixes for sidebar blank screens and session management regressions. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **Xcode 26.3 native Claude Agent SDK integration**: Xcode 26.3 introduced a native integration with the Claude Agent SDK — the same underlying harness that powers Claude Code — giving Apple developers access to Claude Code's full capabilities directly inside Xcode. Source: [Anthropic News](https://anthropic.com/news/apple-xcode-claude-agent-sdk)

- **Cowork now runs on web and mobile**: The Cowork multi-agent collaboration feature (previously desktop-only) now runs on web and mobile, with remote session support in beta, files and session state saved to the user's Claude account, and cross-device sync. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

## Bug Fixes & Performance

- **HTTP 400 errors on third-party endpoints fixed (v2.1.268)**: A regression causing HTTP 400 errors when using Anthropic-compatible third-party LLM endpoints has been resolved. Permission rules on symlinked directories now apply correctly, and prompt caching plus extended thinking no longer break mid-session for SDK sessions. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **Gateway compatibility restored (v2.1.266, Sep 8)**: A regression introduced in v2.1.265 caused `CLAUDE_CODE_USE_GATEWAY` to be incorrectly applied when used alone with API key configurations, breaking LLM-gateway and proxy setups. This was patched within hours by a dedicated hotfix release. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **MCP HTTP servers now connect correctly (v2.1.265)**: MCP servers configured as HTTP were silently failing to connect. This is now fixed, along with MCP startup errors that previously showed servers as "connected with no tools" when they disconnected during tool listing. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

## Community & Ecosystem

- **Claude Code usage limits restructuring (effective Sep 14)**: Anthropic is replacing the temporary 50% Claude Code weekly boost with a permanent 25% increase. Analysis from the community indicates this effectively reduces capacity by ~17% for most users who had come to rely on the temporary boost. The `/limit-reset` command (introduced Sep 3) allows resetting the 5-hour session limit once per week. Source: [Claude Code Updates – Releasebot](https://releasebot.io/updates/anthropic/claude-code)

- **Commerce agent blueprint with Claude Code plugin**: Anthropic launched a commerce agent reference architecture including shopping and merchant agents, guardrails, live demos, and a Claude Code plugin to help teams rapidly build AI-powered shopping experiences. Source: [Claude Code News – mean.ceo](https://blog.mean.ceo/claude-code-news-september-2026/)

- **MCP & plugins guide for 2026**: Community guides covering managed MCP servers, plugin validation improvements, and the `--plugin-dir` folder-of-plugins feature (v2.1.265) are helping teams standardize how they extend Claude Code at scale. Source: [Clarista.io – Claude Code MCP & Plugins Guide](https://www.clarista.io/blog/claude-code-mcp-plugins-guide)

## Roadmap & Announcements

- **GitLab MR recognition (v2.1.259)**: Claude Code now recognizes GitLab merge requests in the same way it handles GitHub PRs, broadening its CI/CD and review workflow support beyond GitHub-only environments. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **OpenTelemetry direct export for Claude apps gateway (v2.1.265)**: The Claude apps gateway now exports telemetry directly to OpenTelemetry collectors, with user metadata (`user.email`, `user.groups`) available for enterprise observability pipelines. A `gatewayInternalNetworks` managed setting was added in v2.1.268 to further tighten network controls. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

## Key Takeaway
The standout development is the rapid stabilization of Claude Code's enterprise gateway layer — nine releases in eleven days have addressed critical bugs in MCP connectivity, third-party endpoint compatibility, and managed settings — while Fable 5.1 as the new default model substantially raises the capability ceiling for all Claude Code users.
