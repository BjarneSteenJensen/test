# Claude Code News Digest — 2026-11-17

## Overview
Claude Code shipped three significant releases this week (v2.1.323–v2.1.326), with the headline addition being **Code Mode** — an experimental opt-in that lets Claude write JavaScript to orchestrate its own tool calls instead of making discrete API round-trips. Security is also front-of-mind today, as three separate issues landed in quick succession: credential exposure from committed `settings.local.json` files, a VS Code extension file-access vulnerability report, and a Cursor marketplace breach involving tampered Claude Code extension builds.

## New Features & Releases

- **Code Mode (v2.1.323, Nov 12 → now enabled with agent teams in v2.1.326, Nov 16)**: An experimental opt-in in which Claude writes JavaScript to call its tools rather than making a separate API round-trip per tool. v2.1.326 extends Code Mode so it can be activated while agent teams are also enabled. The default context window for unrecognized model IDs also rose from 200K to 1M in v2.1.323 (opt out with `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`). Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **v2.1.326 — 59 improvements and 233 bug fixes (Nov 16)**: Adds `OTEL_RESOURCE_INCLUDE_HOST` for host telemetry attributes, a startup warning for malformed `--allowedTools` rules, Ctrl+O to surface hidden startup notices, and a `/status` row that reports when features are disabled. Organizations with the Claude Code + Cowork HIPAA configuration now start in auto mode by default. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **v2.1.325 — VS Code prompt suggestions and sandbox changes (Nov 13)**: Adds tab-accept prompt suggestions in the VS Code panel (`promptSuggestionEnabled: false` to disable), a Console sign-in flow that creates no API key, and a redirect-URL field for MCP sign-in over SSH/WSL/containers. Sandboxed Bash commands now follow the normal permission flow by default. Fixed a security issue in zstd-compressed response decoding. 14 improvements, 88 bug fixes. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **v2.1.323 — Plugin versioning and .docx uploads (Nov 12)**: Plugin authors can now declare `engines["claude-code"]` in `plugin.json`; plugins outside their stated version range are blocked from installing or loading. Artifact uploads now accept `.docx` files. `claude plugin validate` gains TypeScript type-checking for hooks modules. A 30-second heartbeat keeps `claude -p` and SDK sessions alive while long-running hooks execute. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

## Integrations & Extensions

- **IDE extension no longer auto-installs from an IDE terminal**: Claude Code v2.1.323 stopped automatically installing or updating the IDE extension when Claude Code is launched inside an IDE's integrated terminal. Users must now run `/ide` from an external terminal or install via their editor's extensions view. Source: [gradually.ai Claude Code Changelog (November 2026)](https://www.gradually.ai/en/changelogs/claude-code/)

- **Fable 5.2 added as default Fable model (v2.1.321, Nov 9)**: Claude Code 2.1.321 added Claude Fable 5.2 support with a 1M context window. Source: [Releasebot Anthropic November 2026](https://releasebot.io/updates/anthropic/claude-code)

- **Claude Agent SDK — `onFailure: "block"` and MCP fixes**: The renamed Claude Agent SDK (formerly Claude Code SDK) added an `onFailure: "block"` option for hook callbacks, so a failing callback blocks the action instead of silently continuing. MCP server reconnection and `managedSettings` handling of Remote Control toggles were also fixed. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **MCP tool description limit raised from 4,096 to 16,384 characters**: A regression that truncated MCP tool descriptions for new cloud sessions was fixed, restoring the full 16K character limit. Source: [DEV Community — Week of Nov 8, 2026](https://dev.to/aicoding-guide/this-week-in-claude-code-codex-and-gemini-cli-week-of-november-8-2026-485k)

## Bug Fixes & Performance

- **v2.1.325 — zstd decoding security fix (Nov 13)**: A security issue in how Claude Code decoded zstd-compressed server responses was patched. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **v2.1.321 — Four permission/sandbox gaps closed (Nov 9)**: Permission prompts that should have appeared in sandboxed contexts were silently skipped; four such cases were fixed. Source: [DEV Community — Week of Nov 8, 2026](https://dev.to/aicoding-guide/this-week-in-claude-code-codex-and-gemini-cli-week-of-november-8-2026-485k)

- **Hook `"decision": "block"` now enforced in more cases (v2.1.326)**: A hook returning `"decision": "block"` previously did not reliably halt execution; this is now consistently enforced. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

## Community & Ecosystem

- **Security: 2,539 credentials exposed in public GitHub repos via `settings.local.json`**: Researchers (Apiiro) found that passwords and API keys entered into Claude Code's "allow without asking again" prompts are saved to `.claude/settings.local.json`. Copies of that file have been committed to public GitHub repositories — 2,539 credentials across 1,994 repos at the time of disclosure. Users should audit their repositories and add `settings.local.json` to `.gitignore`. Source: [The Hacker News (Nov ~8)](https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html)

- **Security research: VS Code extension can access files outside trusted workspaces**: Researchers disclosed that the Claude Code VS Code extension can present a permission prompt that obscures a file's real path, potentially allowing access to files outside the trusted workspace. Anthropic reviewed the report and does not currently classify it as a security vulnerability. Source: [CyberSecurityNews](https://cybersecuritynews.com/claude-code-vs-code-extension)

- **Cursor marketplace breach — tampered Claude Code extension builds**: Cursor reported that an attacker used a leaked partner credential to push tampered Claude Code extension builds (versions 2.1.312 and 2.1.313) to its built-in marketplace. The malicious builds were available for approximately 11 hours before being pulled. Cursor states the incident is contained. Users of Cursor who installed the extension during that window should verify their installation. Source: [Online Tech Tips](https://www.online-tech-tips.com/cursor-breach-malicious-claude-code-extension/)

- **Game-cloning refusals confirmed on Opus 5.5 + Claude Code**: Anthropic confirmed it added two sentences to Claude Code's system prompt on the Opus 5.5 model to prevent recreating specific existing games. Original games and genre-based games are stated to still be supported. Users also report related refusals for reverse-engineering tasks when using Opus 5.5. Source: [Tom's Hardware](https://www.tomshardware.com/tech-industry/artificial-intelligence/anthropic-confirms-new-claude-code-limits-to-prevent-game-cloning-users-report-opus-5-5-is-also-actively-blocking-reverse-engineering-tasks)

## Roadmap & Announcements

- **Fast mode for Opus 4.8 deprecated — deadline November 30, 2026**: Anthropic deprecated fast mode for the Opus 4.8 model on October 30. As of November 30, fast mode requests on Opus 4.8 will return an error and will not fall back to standard Opus 4.8 speed. Users should migrate to Opus 5.5 to retain fast mode. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **Claude Code SDK officially renamed to Claude Agent SDK**: The rename is now reflected in official Anthropic documentation and changelog entries. The old package names still install but active development and docs have moved to the new naming. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

- **Scheduled tasks now warn before running skills with declared tools/hooks**: `/loop` and scheduled tasks will ask before running any skill that declares `allowed-tools` or hooks. Add `Skill(name)` to `permissions.allow` in settings to bypass the prompt for unattended runs. Source: [Claude Code Changelog](https://code.claude.com/docs/en/changelog)

## Key Takeaway
The most important development this week is the **triple security alert**: committed `settings.local.json` files have already exposed nearly 2,500 credentials on public GitHub, the VS Code extension has an unresolved file-access path-obscuring issue, and Cursor's marketplace was briefly compromised with malicious Claude Code builds — all in the same week. Users should immediately add `settings.local.json` to `.gitignore`, audit existing repos for committed credentials, and verify their IDE extension versions.
