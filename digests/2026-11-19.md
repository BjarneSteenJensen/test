# Claude Code News Digest — 2026-11-19

## Overview
Claude Code continues its rapid release cadence with four versions shipped in the last week (v2.1.325–v2.1.328), culminating in today's v2.1.328 that expands Auto mode to major cloud providers including Amazon Bedrock, Google Cloud, Microsoft Foundry, and Azure. The headline experimental feature of the week is **Code Mode**, which lets Claude write a JavaScript script of tool calls and execute them in one shot, and a significant security advisory affects anyone who installed Claude Code through Cursor in late October.

---

## New Features & Releases

- **v2.1.328 — Auto Mode on Cloud Platforms (November 19, 2026)**: Auto mode is now available for Claude Opus 4.6 and Sonnet 4.6 on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry, and the Claude apps gateway. Interactive sessions with no explicit permission mode now start in auto mode by default. The release also adds `"onFailure": "block"` support for `mcp_tool` hooks, refocuses `/code-review` to bugs and CLAUDE.md violations only (use `/simplify` for cleanups), and fixes a zsh crash on words beginning with `=`. Source: https://code.claude.com/docs/en/changelog

- **v2.1.327 — MCP stdin, WorkTree Safety & /status Diagnostics (November 17, 2026)**: `claude mcp add-json <name> -` now reads server JSON from stdin, keeping tokens off the command line. `ExitWorktree` will ask before removing a worktree that may hold unsaved work. The new `/status` command lists broken agent, skill, and command files, keybinding errors, and unavailable sandboxes. Auto mode now ignores over-broad allow rules such as `Bash(pnpm dlx *)`. Source: https://code.claude.com/docs/en/changelog

- **v2.1.326 — Code Mode for Agent Teams (November 16, 2026)**: Code Mode, the experimental opt-in that has Claude write a JavaScript script to execute multiple tool calls in one pass, now works while agent teams are enabled. Many Bash and PowerShell commands were tightened to require explicit approval or are now refused. Organizations with the Claude Code + Cowork HIPAA configuration start sessions in auto mode by default. Source: https://code.claude.com/docs/en/changelog

- **v2.1.325 — Sandbox Permission Flow & VS Code Suggestions (November 13, 2026)**: Sandboxed Bash commands now follow the normal permission approval flow; set `autoAllowBashIfSandboxed: true` to restore the previous auto-approval behavior. Scheduled tasks and `/loop` now ask before running a skill that declares `allowed-tools` or hooks — add `Skill(name)` to `permissions.allow` to run unattended. VS Code gains prompt suggestions (disable with `promptSuggestionEnabled: false`). `claude remote-control` now exits with distinct status codes (4 = stopped itself, 69 = failed to register) for service managers. Source: https://code.claude.com/docs/en/changelog

- **Code Mode Announced (Experimental)**: An experimental opt-in feature where Claude writes a piece of JavaScript that chains multiple tool calls, then Claude Code runs it in your session in one shot. This can significantly reduce latency for multi-step tasks. Code Mode is off by default and toggled in settings. Source: https://releasebot.io/updates/anthropic/claude-code

- **Claude Fable 5.2 as Default Fable Model (v2.1.321)**: Claude Fable 5.2 (`claude-fable-5-2`) was made the default Fable model in Claude Code as of v2.1.321 earlier in November. Source: https://releasebot.io/updates/anthropic/claude-code

## Integrations & Extensions

- **MCP Background Tasks (v2.1.319)**: When an MCP server runs a tool call as a task, Claude Code now immediately moves it to the background and surfaces the result when it finishes. A new env variable `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` lets users opt out of this behavior and wait inline. Source: https://code.claude.com/docs/en/changelog

- **Claude Code Projects: Proactive Coordinator & New Commands (November 13)**: Claude Code Projects received a proactive coordinator mode, read-only thread links, reminder support, and two new commands — `/btw` and `/fork` — for use inside projects. These make it easier to coordinate multi-agent work and hand off context between sessions. Source: https://claudenetwork.com/news

- **JetBrains Claude Code Chat Plugin v1.4.0**: The third-party Claude Code Chat plugin for JetBrains IDEs released v1.4.0 on November 11, 2026, adding compatibility with the 2026.3 family of IntelliJ-based IDEs. This is a community plugin separate from Anthropic's official JetBrains extension. Source: https://plugins.jetbrains.com/plugin/31507-claude-code-chat

- **OpenCode 2.2.3 Adds Claude Agent SDK Provider (October 30)**: OpenCode 2.2.3 added a Claude Agent provider that runs the user's locally installed Claude Code binary through the Agent SDK, enabling Claude subscriptions to be used inside OpenCode. Source: https://releasebot.io/updates/anthropic/claude-code

- **Claude Agent SDK — Hook Arrays & Breaking Changes (v0.3.327 / v0.2.184)**: The TypeScript SDK reached 0.3.327 and the Python SDK 0.2.184 as of November 18. Hook options must now be arrays (a breaking change enforced at runtime). Sandboxed Bash is no longer auto-approved without `autoAllowBashIfSandboxed`. The `onFailure: "block"` callback option blocks a failing hook's action. Source: https://www.developersdigest.tech/blog/claude-agent-sdk-whats-new-2026

## Bug Fixes & Performance

- **zstd Security Fix (v2.1.325)**: A security issue in how zstd-compressed network responses are decoded was patched in v2.1.325 (November 13). Users should update immediately. Source: https://code.claude.com/docs/en/changelog

- **Permission & Sandbox Gap Fixes (v2.1.321)**: Four permission and sandbox gaps were closed in v2.1.321, reducing the surface for unintended actions in automated and agent-team workflows. Source: https://releasebot.io/updates/anthropic/claude-code

- **Zsh Word-Equals Bug (v2.1.328)**: A crash on zsh commands where words begin with `=` (e.g., `echo ====`) is fixed in today's v2.1.328. An Esc keypress being swallowed at permission prompts is also resolved. Source: https://code.claude.com/docs/en/changelog

- **MCP stdio Startup Failure (v2.1.327)**: `/mcp` now shows why a local stdio MCP server failed to start, making it much easier to debug broken server configurations. The `mcp add --scope project` command no longer silently overwrites `.mcp.json` files missing an `mcpServers` key. Source: https://code.claude.com/docs/en/changelog

## Community & Ecosystem

- **Cursor Security Incident — Malicious Claude Code Extension**: Cursor disclosed that an attacker used a leaked partner credential to publish tampered Claude Code extension builds (versions 2.1.312 and 2.1.313) to the Cursor marketplace on or around October 29, 2026. Cursor's November 13 update says the incident is considered contained and asks affected users to follow their remediation steps. Anyone who installed `Anthropic.claude-code` versions 2.1.312 or 2.1.313 through Cursor should review Cursor's security advisory. Source: https://www.online-tech-tips.com/cursor-breach-malicious-claude-code-extension/ *(Note: this domain was not reachable in this session's network; verify via Cursor's own status page.)*

- **Community Visual Studio 2026 Extension**: An unofficial, community-built extension (`firish.bridgev1`) adds Claude Code integration to Visual Studio 2026, including native diff accept/reject, a live debugger Claude can drive, Roslyn code navigation, and Test Explorer integration. No official Anthropic VS 2026 extension exists yet. Source: https://github.com/firish/claude_code_vs

## Roadmap & Announcements

- **Fast Mode for Opus 4.8 Deprecated — Retiring November 30**: Fast mode for Claude Opus 4.8 was deprecated on October 30, 2026 and will be removed on November 30, 2026. Users relying on fast mode with Opus 4.8 should migrate to Opus 4.6 or another model before the end of the month. Source: https://releasebot.io/updates/anthropic/claude-code

- **Self-Hosted Runner Enhancements**: v2.1.328 added `--repository-folder`, `--hook-label`, and `--metadata key=value` flags to the self-hosted runner, giving organizations more control over how agent jobs run on their own infrastructure. Source: https://code.claude.com/docs/en/changelog

- **Auto Mode Classifier Removal**: Auto mode no longer falls back to the built-in classifier in recent releases, simplifying its decision logic and reducing false-positive permission prompts. Source: https://www.gradually.ai/en/changelogs/claude-code/

---

## Key Takeaway
Today's v2.1.328 brings Auto mode to all major cloud provider deployments (Bedrock, GCP, Foundry, Azure), marking a significant step toward zero-configuration enterprise adoption — but the most urgent action item this week is for Cursor users to check whether they installed the compromised Claude Code extension versions 2.1.312 or 2.1.313 and follow Cursor's remediation steps.
